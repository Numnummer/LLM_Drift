# Определение дрейфа целей в LLM-агентах

Исследовательский проект ИТМО / AlmetTech. Руководитель: Вячеслав Шаламов.

Сейчас идёт **задача 1: формализация типов дрейфа целей**. Сдаваемые артефакты —
B7.1–B7.5, см. @docs/plan.md. Задачи 2–7 (сценарии, метрики, сравнение моделей,
детектор, онлайн-модуль, оценка) пока НЕ в работе — не начинай их по своей инициативе.

## Источники истины — не переписывать без явной просьбы

- @docs/taxonomy.md — определения типов D1–D8 и не-дрейфов N1–N4, условия C1–C3,
  решающая процедура. Это результат отдельной исследовательской работы.
  **Код обязан соответствовать документу, а не наоборот.** Нашёл противоречие между
  кодом и документом — остановись и спроси, а не «почини» определение.
- @docs/plan.md — фазы 0–4, приёмочные критерии, риски.
- @docs/annotation_guide.md — как люди размечают траектории.
- @docs/related-work.md — обзор литературы и оценка качества источников.

## Ключевые инварианты

- Проверки в `classify()` выполняются **строго в порядке решающего дерева**
  (taxonomy.md, раздел «Решающая процедура»). Порядок — это семантика, а не
  оптимизация. Не переупорядочивать, не объединять «для скорости», не превращать
  цепочку в словарь-диспетчер.
- Условие **C1 требует контрфактического прогона** с санированным контекстом.
  Любой `Step` обязан хранить воспроизводимое `env_state`. Без этого C1 не
  проверяется и весь пайплайн теряет смысл.
- Каждый `Verdict` обязан содержать `evidence` — индексы шагов, на которых основан
  вывод. Вердикт без evidence не принимается. Исключение — `ok`: без отклонения
  ссылаться не на что.
- Судейский слой (LLM) — только через протокол `Judge` из `src/taxonomy/judge.py`.
  Никаких прямых вызовов API из `checks.py`: судья должен быть заменяем на человека
  и на другую модель, иначе в задаче 7 не отделить ошибки судьи от ошибок процедуры.
- Метрики согласия считаются **отдельно** по бинарной метке (дрейф / не дрейф) и по
  12 типам. Усреднённый κ маскирует редкие классы (D3, D8, N3).

## Чего не делать

- Не изобретать новые типы дрейфа, не переименовывать и не удалять существующие.
  Состав `Label` меняется только решением человека после фазы 2 (см. гейт в plan.md).
- Не подгонять пороги под целевой κ. Пороги фиксируются до разметки и меняются
  только вместе с документом.
- Не «улучшать» таксономию по найденным в сети источникам. Качество литературы уже
  оценено в related-work.md, часть популярных источников там помечена как ненадёжная.
- Не добавлять зависимости без спроса.
- Не коммитить содержимое `data/` (траектории и разметку) без явной просьбы.

## Стек и конвенции

Python 3.11, uv, pytest. pandas / scikit-learn, sentence-transformers.
Локальный Qwen через vLLM для судейского слоя и для будущих пробников.
FastAPI — только для модуля задачи 6, сейчас не нужен.
Типизация обязательна; схемы — через dataclass. Функции-проверки чистые:
никакого глобального состояния, никаких сайд-эффектов кроме вызовов `probe`/`judge`.
