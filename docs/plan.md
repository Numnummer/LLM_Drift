# План работ: задача 1 (формализация типов дрейфа)

Горизонт ~4 недели при 15–20 ч/нед. Порядок намеренный: **разметка идёт до кода**.
Классификатор, написанный по неоткалиброванным определениям, закодирует границы,
которые развалятся на первой реальной траектории.

---

## Фаза 0 — Корпус траекторий (2–3 дня)

Цель: ~150 траекторий, покрывающих все классы, включая не-дрейф.

| Источник | Что даёт | Классы |
|---|---|---|
| `RaunoArike/goal-drift-evals`, прогнать самим | эталон с давлением и переключением фаз | D1, D2, D3, D5 |
| Свои прогоны Qwen на той же среде | доступ к активациям, дешёвые перезапуски | все |
| Длинные прогоны без давления | негативный контроль | N1, D6 |
| TaskTracker (Microsoft) | готовые примеры инъекций | D7 |
| Искусственно урезанный контекст | синтетика для редкого класса | D8 |

**Блокирующее требование.** Условие C1 требует контрфактического прогона, значит
логгер обязан сохранять воспроизводимое состояние среды на каждом шаге.
Проверить воспроизводимость на 5 траекториях **до** набора 150.

**Готово, когда:** `scripts/run_env.py` пишет логи в схеме `Step`; реплей
произвольного шага с очищенным контекстом воспроизводится; 150 траекторий собраны.

## Фаза 1 — Черновик определений (3–4 дня) → B7.1

Пишется быстро и намеренно черново: будет переписан после фазы 2.

1. Формализовать `G0` для конкретной среды, выписать `C` явным списком.
2. Зафиксировать пороги в условиях C1–C3 (все `TODO(порог)` в taxonomy.md).
3. Описать D1–D8 и N1–N4 по шаблону: определение, формальный признак, пример,
   ближайший сосед и чем отличается.

Секция «чем отличается от соседа» — важнейшая. Пары, которые гарантированно
поплывут: D1/D2, D5/N1, D4/D8, D1/N2.

**Готово, когда:** каждый тип имеет признак, вычислимый из лога, и секцию соседа.

## Фаза 2 — Гайдлайн, разметка, κ (7–9 дней) → B7.3

Ядро работы. Три итерации.

- **Итерация 1 (20 траекторий):** два разметчика независимо, затем разбор **всех**
  расхождений. Цель — не κ, а список мест двойного прочтения. Гайдлайн переписывается.
- **Итерация 2 (30 траекторий):** то же, считается κ. Ожидаемо 0.4–0.6 — норма.
- **Итерация 3 (50–100 траекторий):** замер. Целевое κ ≥ 0.7 по бинарной метке,
  ≥ 0.6 по типам.

Если по какой-то паре κ упорно < 0.5 после двух итераций — **типы сливаются**.
Различие, которое два обученных человека не воспроизводят, не существует
операционально. Честный отчёт об этом — результат, а не провал.

Разметка ведётся **по шагам**: метка ставится на шаг `t*` первого отклонения плюс
тип. Так бесплатно получается ground truth для задержки обнаружения в задаче 7.

**Главный аналитический артефакт фазы:** матрица несогласия между разметчиками.

### ГЕЙТ после фазы 2

Остановиться и решить человеком: остаётся ли таксономия из 12 меток или
схлопывается до 6–8. Агенту это решение не делегируется.

## Фаза 3 — Исполнимая процедура (5–6 дней) → B7.2

Только после стабилизации гайдлайна. Архитектура — точное отражение решающего
дерева: каждая проверка отдельной функцией, возвращающей вердикт **и обоснование**.

Три уровня проверок по стоимости:

- **Детерминированные** (парсер): D8, локализация D7, повторы для D6.
- **Контрфактические** (перезапуск модели): C1/N1, перезапрос для N2.
- **Судейские** (LLM): `al(a_t)`, D1 vs D2, извлечение заявленной цели.

Судейский слой обязан быть заменяемым (интерфейс `Judge`), иначе в задаче 7 не
отделить ошибки судьи от ошибок процедуры.

**Валидация:** прогнать `classify` на размеченном корпусе, посчитать согласие с
человеческим консенсусом. Целевое — не ниже межчеловеческого κ. Если хуже —
разбирать ошибки по классам и чинить проверки, а не пороги.

## Фаза 4 — Маппинг и покрытие (2–3 дня) → B7.4, B7.5

**B7.4 — маппинг на MAST.** Таблица «наш тип → FM-код → полное / частичное / нет
аналога». Заведомые: D1 ↔ FM-2.3, D4 ↔ FM-1.1, D6 ↔ FM-1.4, D3 ↔ FM-1.5,
маркер «заявленное vs фактическое» ↔ FM-2.6. Явно назвать, чего в MAST нет:
D5 и разделение D7/D1 по источнику — это дельта-вклад работы.

**B7.5 — таблица покрытия.** Строки — типы; столбцы: есть ли готовый детектор,
ссылка, качество, что не покрыто. Вывод таблицы — обоснование, почему задачи 5–6
фокусируются на D1–D5.

## Приёмочные критерии

| Артефакт | Критерий |

| B7.1 taxonomy.md | каждый тип имеет вычислимый из лога признак и секцию отличия от соседа |
| B7.2 классификатор | тесты проходят на всех 12 метках; согласие с консенсусом ≥ межчеловеческого κ |
| B7.3 разметка | κ ≥ 0.7 бинарно и ≥ 0.6 по типам; ≥ 50 траекторий двумя разметчиками |
| B7.4 маппинг | все типы отображены; названы ≥ 2 явления вне MAST |

## Риски

- **κ не растёт выше 0.5 по паре.** Не тюнить гайдлайн бесконечно: две итерации
  без прогресса = решение о слиянии типов.
- **Контрфактический прогон невоспроизводим.** Чинить на фазе 0. Запасной вариант:
  три прогона baseline, требование ≥ 2 целесогласованных.
- **Один разметчик.** Если второго человека нет — сильная модель как «второй
  разметчик», но с оговоркой в отчёте: κ человек–модель не эквивалентен
  κ человек–человек и завышает согласие по лёгким классам.
- **Классовый дисбаланс.** D3, D8, N3 в естественных прогонах почти не встречаются.
  Досинтезировать намеренно, метрики согласия по редким классам считать отдельно.

## Использование кодогенерации

Требование проекта — обязательное использование Cursor / Codex / Claude Code.
Кодогенерация хорошо закрывает фазы 0 и 3 (схемы, парсеры, обвязка, тесты) и
плохо — фазы 1 и 2. Определения и гайдлайн пишутся руками: модель выдаст
правдоподобную таксономию, которая не выдержит разметки.
