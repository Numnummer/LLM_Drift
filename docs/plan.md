# План работ: задача 1 (формализация типов дрейфа)

Горизонт ~4 недели при 15–20 ч/нед.

**Пересмотр 2026-10-09 (решение человека).** Ручная разметка двумя людьми
отменена: второго человека нет, а разметка одним человеком медленная и
ошибочная из-за усталости (итерация 1 остановлена на 3 траекториях из 20).
Корректность и воспроизводимость таксономии теперь измеряются без массовой
ручной разметки: эталонами с известным ответом (агенты по сценарию, парные
траектории), повтором процедуры (test–retest) и панелью локальных моделей-
разметчиков разных семейств, прошедших квалификацию на эталоне. Человек
разбирает только противоречия и принимает решение на гейте. Фазы 0, 1 и 4 не
менялись; фазы 2 и 3 переписаны, их порядок по существу обратный: эталоны и
процедура нужны раньше замеров.

---

## Фаза 0 — Корпус траекторий (2–3 дня)

Цель: ~150 траекторий, покрывающих все классы, включая не-дрейф.

| Источник | Что даёт | Классы |
|---|---|---|
| `RaunoArike/goal-drift-evals`, прогнать самим | эталон с давлением и переключением фаз | D1, D2, D3, D5 |
| Свои прогоны Qwen на той же среде | доступ к активациям, дешёвые перезапуски | все |
| Длинные прогоны без давления | негативный контроль | N1, D6 |
| TaskTracker (Microsoft) | готовые примеры инъекций | D7 |
| Искусственно урезанный контекст | синтетика для редкого класса | D8 |

**Блокирующее требование.** Условие C1 требует контрфактического прогона, значит
логгер обязан сохранять воспроизводимое состояние среды на каждом шаге.
Проверить воспроизводимость на 5 траекториях **до** набора 150.

**Готово, когда:** `scripts/run_env.py` пишет логи в схеме `Step`; реплей
произвольного шага с очищенным контекстом воспроизводится; 150 траекторий собраны.

## Фаза 1 — Черновик определений (3–4 дня) → B7.1

Пишется быстро и намеренно черново: будет переписан после фазы 2.

1. Формализовать `G0` для конкретной среды, выписать `C` явным списком.
2. Зафиксировать пороги в условиях C1–C3 (все `TODO(порог)` в taxonomy.md).
3. Описать D1–D8 и N1–N4 по шаблону: определение, формальный признак, пример,
   ближайший сосед и чем отличается.

Секция «чем отличается от соседа» — важнейшая. Пары, которые гарантированно
поплывут: D1/D2, D5/N1, D4/D8, D1/N2.

**Готово, когда:** каждый тип имеет признак, вычислимый из лога, и секцию соседа.

## Фаза 2 — Эталоны и воспроизводимость (7–9 дней) → B7.3

Цель: показать, что определения однозначны (воспроизводимость) и что процедура
находит то, что заложено (корректность), — без массовой ручной разметки.
Термины по Artstein & Poesio (2008): согласие измеряет надёжность, а не
валидность, поэтому нужны обе половины.

**Эталоны с известным ответом (корректность).**

- **V1. Агенты по сценарию.** `ScriptedPolicy` раннера с заложенным поведением:
  дрейф к конкурирующему кластеру с шага k (D1), частичный (D2), прекращение
  проверок перед покупкой (D4), прекращение вложений (D5), повтор выполненных
  сделок (D6), инструментальная цель после выполнения условия (D3), реакция на
  инъекцию (D7), нарушение ограничений после их урезания (D8), следование
  авторизованной смене (N3), неверное прочтение с шага 1 (N4), чистый контроль
  (ok). Среда честно прогоняет действия; C1 считается настоящим LLM-агентом.
  N1 и N2 сценарием не заложить (зависят от поведения LLM) — они проверяются в V2
  и разбором. ~3 траектории на класс, ~35 всего.
- **V2. Парные траектории.** Прогоны с одним сидом совпадают до шага возмущения
  k, поэтому расхождение после k — причинный эффект возмущения: инъекция (k = 4),
  урезание C (4), авторизованная смена (5), нормативный конфликт (4), усиленное
  давление (3; для strict_pressure нужен контрольный сценарий без него).
  Если пара не разошлась, агент не отреагировал — правильный ответ `ok` для
  эффекта возмущения.
- **V3. Вмешательства** (по возможности): реплей шага с убранным давлением,
  возвращённым ограничением, убранной инъекцией. Предсказания записываются до
  прогона.

**Воспроизводимость.**

- **R1. Повтор процедуры (test–retest).** Каждая траектория классифицируется
  K = 5 раз с разными сидами санированных прогонов, перезапроса и судьи; α
  Криппендорфа между повторами — бинарно, по типам и по каждому классу.
- **R2. Панель моделей-разметчиков.** ≥ 3 локальные модели разных семейств с
  режимом рассуждений размечают по annotation_guide.md в два прохода (t* →
  справки → метка). Не берутся Qwen (семейство агента), Claude (семейство автора
  таксономии), дистилляты на базе Qwen/Llama. В панель входят только модели,
  прошедшие **квалификацию на V1**: иначе низкая α не отличает неоднозначность
  определений от слабости модели. α Криппендорфа между моделями — бинарно, по
  типам, по классам; матрица несогласия — вход для гейта.
- **Устойчивость явления** (описательно, не критерий): доля сидов сценария, в
  которых возникает ожидаемый класс.

**Человек — V4, разбор противоречий.** Только случаи, где V1–V3, R1 или R2 дают
противоречие (ожидается 10–15 за фазу), на свежую голову. Итог разбора правит
annotation_guide.md и при необходимости taxonomy.md.

**Главный аналитический артефакт фазы:** матрица несогласия панели R2 вместе со
списком провалов процедуры на эталонах V1–V2.

### ГЕЙТ после фазы 2

Остановиться и решить человеком: остаётся ли таксономия из 12 меток или
схлопывается до 6–8. Кандидат на слияние — пара типов, по которой α панели R2
< 0.5 или процедура систематически путает её на эталонах. Уже вынесено: N4 →
N1 (решение 2026-10-01). Агенту это решение не делегируется. Слияние задним
числом не равно разметке с меньшим числом категорий: после слияния α
пересчитывается на новой разметке панели.

## Фаза 3 — Исполнимая процедура (5–6 дней) → B7.2

Нужна раньше замеров фазы 2: R1, V1–V2 и квалификация панели меряют именно её.
Архитектура — точное отражение решающего дерева: каждая проверка отдельной
функцией, возвращающей вердикт **и обоснование**.

Три уровня проверок по стоимости:

- **Детерминированные** (оракул, парсер): D8, локализация D7, N3, D4, D5, D3,
  доля согласованных шагов для D1/D2, повторы для D6.
- **Контрфактические** (перезапуск модели): C1/N1, перезапрос для N2.
- **Судейские** (LLM): обоснованность отклонения для N2, устаревшая модель
  состояния для D6. Судья — локальная модель **не из панели R2**: иначе процедура
  и разметчик ошибаются одинаково, и их согласие завышено.

Судейский слой обязан быть заменяемым (интерфейс `Judge`), иначе в задаче 7 не
отделить ошибки судьи от ошибок процедуры.

**Валидация:** точность на V1 и V2, α повторов (R1), согласие процедуры с
большинством панели R2. Если хуже порогов — разбирать ошибки по классам и чинить
проверки, а не пороги.

## Приёмочные критерии

Пороги зафиксированы 2026-10-09 до замеров и меняются только вместе с этим
документом. Шкала для α — Криппендорфа: ≥ 0.8 надёжно, ≥ 0.667 — нижняя граница
для осторожных выводов. Все α — с бутстреп-интервалами; по редким классам, где
выборка меньше минимума Криппендорфа, оценка помечается как ненадёжная.

| Артефакт | Критерий |
|---|---|
| B7.1 taxonomy.md | каждый тип имеет вычислимый из лога признак и секцию отличия от соседа |
| B7.2 классификатор | тесты на всех 12 метках; на V1 тип угадан ≥ 0.9, t* точно ≥ 0.9; на расходящихся парах V2 t* ∈ [k, k+1] и ожидаемый тип ≥ 0.8; согласие с большинством панели R2 не ниже α самой панели |
| B7.3 воспроизводимость | R1: α ≥ 0.8 бинарно и ≥ 0.667 по типам; R2: панель ≥ 3 семейств, каждая модель прошла квалификацию (на V1 тип ≥ 0.8, t* ±1 ≥ 0.8), α ≥ 0.8 бинарно и ≥ 0.667 по типам; ≥ 44 траектории корпуса + V1 |
| B7.4 маппинг | все типы отображены; названы ≥ 2 явления вне MAST |
| B7.5 покрытие | для каждого типа статус со ссылкой или пометкой «нет решения» |

## Риски

- **Модели-разметчики слабы.** Локальные модели на 8 ГБ заметно слабее облачных.
  Квалификация на V1 отсеивает некомпетентных; если её проходят меньше трёх
  семейств — панель из двух с оговоркой или облачная модель через API.
- **Согласие моделей ≠ согласие людей.** Модели разделяют общие предубеждения и
  завышают согласие на лёгких классах. Называть в отчёте; спорные границы
  (D1/N2, D4/D8) — через разбор человеком (V4).
- **Эталон V1 искусственен.** Агенты по сценарию проверяют, что процедура
  реализует определения, но не что определения адекватны реальному дрейфу LLM.
  Поэтому V1 дополняется V2 на настоящем агенте.
- **α по паре < 0.5.** Не тюнить гайдлайн бесконечно: две правки без прогресса =
  кандидат на слияние типов на гейте.
- **Классовый дисбаланс.** D3, D7, D8, N3 в естественных прогонах редки.
  Досинтезировать (V1, сценарии), метрики по редким классам считать отдельно.
- **Контрфактический прогон невоспроизводим.** Закрыто на фазе 0: прогон с тем же
  сидом совпадает полностью.

## Использование кодогенерации

Требование проекта — обязательное использование Cursor / Codex / Claude Code.
Кодогенерация хорошо закрывает фазы 0 и 3 (схемы, парсеры, обвязка, тесты,
агенты по сценарию) и плохо — определения. Определения, гайдлайн и решения на
гейте остаются за человеком: модель выдаст правдоподобную таксономию, которая не
выдержит проверки.
